# Contributing to CareerOS

Thank you for your interest in contributing to CareerOS.

CareerOS is an open-source project focused on helping software engineers, AI engineers, and computer science students build repeatable, high-quality career systems.

Our goal is to maintain a repository that values clarity, quality, and practical impact over quantity.

---

# Philosophy

Every contribution should answer one question:

> Does this make someone's job search more effective?

If the answer is no, it probably does not belong in CareerOS.

---

# Guiding Principles

Every contribution should be:

- Practical
- Reusable
- Well documented
- Easy to follow
- Based on real workflows
- Ethical

CareerOS does not promote:

- Fake experience
- Misleading resumes
- Keyword stuffing
- Spam networking
- AI-generated dishonesty

---

# Repository Structure

```
docs/
prompts/
templates/
workflows/
automation/
resources/
trackers/
assets/
```

Please place new content in the correct directory.

---

# Before You Contribute

Before opening a Pull Request, ask yourself:

- Does this solve a real problem?
- Is the information accurate?
- Can someone reuse this?
- Is it well documented?
- Does it duplicate existing content?

If a similar document already exists, improve it instead of creating another version.

---

# Documentation Standards

Every document should follow this structure.

```
# Title

## Purpose

## Audience

## Prerequisites

## Step-by-Step Guide

## Example

## Best Practices

## Common Mistakes

## Related Resources
```

Consistency makes the repository easier to maintain.

---

# Prompt Standards

Every AI prompt should include:

- Purpose
- Inputs
- Outputs
- Example
- Limitations
- Expected Result

Avoid publishing prompts without context.

---

# Workflow Standards

Workflows should focus on outcomes rather than individual prompts.

Example:

Job Description

↓

Resume Analysis

↓

ATS Optimization

↓

Application

↓

Interview Preparation

This is preferred over isolated prompt collections.

---

# Commit Message Convention

CareerOS follows Conventional Commits.

Examples:

```
feat: add LinkedIn optimization workflow

docs: create networking strategy

fix: correct ATS scoring example

refactor: reorganize workflow documentation

chore: update repository structure
```

---

# Pull Request Checklist

Before submitting a Pull Request:

- Documentation is complete.
- Examples are included.
- Formatting is consistent.
- Internal links work.
- No duplicate content exists.

---

# Code of Conduct

Be respectful.

Provide constructive feedback.

Assume positive intent.

CareerOS is a collaborative learning project.

---

# Questions?

Open a GitHub Issue before implementing large changes.

We are happy to discuss ideas before development begins.
